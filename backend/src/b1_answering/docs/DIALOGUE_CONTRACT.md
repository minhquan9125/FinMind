## API và kiến trúc

`DialogueSession(session_id=None, today=None)` facade composition trên existing `src.retrieval_orchestration.retrieval_flow.conversation.ChatSession`. `await ask(text)->dict`, `reset()`, `.session_id`, `.last_result` deepcopied, `context_summary()->str`. Mỗi instance có bộ nhớ riêng. Không dùng privateattributes của core; dùng last_decision/last_result public, hoặc state của facade. Constructor lazyimport core. Core read-only runtime được cung cấp để chạy tests thật, không gửi fullcore vào modelcontext.

Core ChatSession(session_id=None,today=None) có async ask(text), syncreset, last_decision/last_result deepcopies, context_summary. last_decision có decision,reason_code,intent,missing_fields,slots,scope. slots: companies list[{ticker,origin,...}], metric{raw,code},period{raw,year,quarter,start,end,granularity,measure_basis,origin}|None, reporting_entity... Scope: companies list[str], periods list[ISO enddate],metric_code,reporting_entity,measure_basis,source_type. last_result là {request_id,query_id,execution_mode:'FIXTURE',b1_decision,status,reason_code,message,scope,clarification,evidence_pack,errors}. statusASK_CLARIFICATION có clarification tiếngViệt; missing_fields từ last_decision: companies,metric.code,period,period.measure_basis,reporting_entity. Core handles full supported questions, bareknowncompany, fullyspelled metric updates, year replies, explicitcorrections, multiplechoices, relativeperiods. Core does NOT understand short 'sau'/'trước' or general unsupportedmetrics. Do not assume ChatSession is in orchestrator; import conversation.

Use declarative normalization tables + pending-field state, never a hardcoded response for one sentence/ticker/year. Accent folding via unicodedata. Safe normalization: common typo `lợi nhuân` -> lợi nhuận; whole-word unambiguous metric abbreviations LNST/LNTT/TTS -> lợi nhuận sau thuế/trước thuế/tổng tài sản (no fuzzy tickers or guessing numbers). Short aliases `sau`, `sau nhé`, `chọn sau`, `sau đi`, `trước`, `trc`, accented/unaccented variants map ONLY when last turn explicitly awaiting profit before/after choice. Use missing_fields + active topic/clarification, not globally replacing words. Bare 'sau' with no appropriate context must ask clarify, NOT become ticker SAU, profit guess, or SEARCH. Strip only bounded conversational prefix/suffix around an exact alias, not arbitrary residual prose. Recognize clear before/after correction (e.g. 'không phải sau, trước') in pending profit-choice state; ambiguous both before+after without explicit correction asks again.

## General unsupported and ambiguous indicators

Declarative registry for recognized but unsupported categories: debt (`nợ`, `nợ phải trả`, `tổng nợ`), revenue (`doanh thu`), equity (`vốn chủ sở hữu`), EPS, ROE, ROA, P/E, P/B. Do not fabricate mappings to supported code or data. A clear request for these should return UNSUPPORTED/UNSUPPORTED_METRIC, name requested indicator and preserve explicit company/period in scope; message lists supported indicator families and says fixture limitation. Don't silently reinterpret as old supported question.

When text contains different indicator families (including 'nợ ... sau thuế', tax qualifier implies alternative profit category), ask which indicator: reason_code AMBIGUOUS_METRIC, status ASK_CLARIFICATION, evidence_pack:null. Preserve explicit company and period while awaiting answer. This applies generally to combinations of recognized supported/unsupported families, NOT just debt+profit; e.g. 'doanh thu và lợi nhuận FPT2025', 'tổng tài sản và lợi nhuận BID2025'. Never select first indicator by regexorder. Explicit comparison/trend requests of SAME indicator should still delegate to core. Preserve company/year when next reply selects one option, e.g. debt+aftertax FPT2025 -> 'lợi nhuận sau thuế' -> core scope PROFIT_AFTER_TAX,FPT,2025. Choosing debt -> UNSUPPORTED with FPT/2025, not financial answer. Ambiguous company/period should remain unresolved and ask again, not choose a match silently.

Custom envelope stays compatible with old fixed fields. Emit new request_id, no evidence or query, status+reason_code+clarification/message, execution_modeFIXTURE. No financial numbers or fake sources. Custom partialscope must use same key names as core, only explicitly supplied companies/periods, not invented currentyear. For remembered company/year, compose canonical supported question only after user chooses indicator. New complete question replaces previous pendingcontext; /moi via reset clears both facade and delegated context. Empty/unrecognized answer must not erase remembered slots or call generation. If answer remains vague, say what field is still needed with useful examples; do not promise arbitrary natural-language coverage.
